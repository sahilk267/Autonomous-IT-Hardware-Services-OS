APEX IT HARDWARE & SERVICES OS

Desktop configuration

Install once, connect whenever your server is deployed. No server URL, database credential or API key is baked into the installer. Change the connection later using Server → Configure / Change Server.

1 · Where should Apex run?
Only enter your organization's verified HTTPS domain — no database URL, credentials, API keys, or /api path. Your login and business data go straight to that server over HTTPS.

A blank address is allowed before deployment. The installer and app can remain unconfigured safely. Once live, enter the URL and select Verify & Connect. Your old server credentials are not copied to another domain.

The Windows account must have private read/write access. Changing the folder later requires a backup and manual migration.
Use a pre-provisioned, non-superuser, non-BYPASSRLS role. Never enter a migration-owner connection here.

For dynamic mode, users enter the workspace UUID and their own credentials at login. The database administrator must provision each organization separately.

2 · Optional LOCAL server integrations

Hosted mode configures these credentials on your deployment server, never on the employee's desktop.

3 · Local server administrator

For a new local database, Apex starts the embedded backend, then asks for a Business Owner username and 12+ character password. A random bootstrap token stays in Windows DPAPI-protected storage. For an existing remote deployment, your server administrator controls accounts and setup — this client does not know the server's setup secret.

Security and switching

Hosted connections require a valid HTTPS certificate and a compatible Apex API handshake. Switching modes or remote domains never migrates records; your previous server/data stay separate. Always verify the domain with your deployment administrator.

Unsigned preview installers can trigger SmartScreen warnings. Distribute a signed build after Windows acceptance tests.
